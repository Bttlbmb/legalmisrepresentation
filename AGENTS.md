# Website instructions

This repository contains the public static viewer. Research belongs in the separate backend repository.

- Preserve the current layout, navigation, responsive rules, and behavior unless the user asks to change them.
- Edit the template in `src/page.html` for an authorized interface change. Its single `/*__DATA__*/null` marker is replaced by the backend.
- Do not edit case text in `dist/`; change its subject's backend JSON and regenerate.
- Serve only `dist/` on loopback for preview. GitHub Pages publishes that same folder at https://bttlbmb.github.io/legalmisrepresentation/. The website must work without a running backend.
- Do not add raw research captures, local paths, credentials, or private backend notes to public output.
- After rebuilding, run the backend's `build --check`, check inline JavaScript syntax, and inspect the affected routes in a browser.
- Commit website changes separately from backend changes. Pushing changes to `dist/`, the route test, or the Pages workflow to `main` deploys automatically. Keep research-only tasks local unless publication is authorized.
- Pages uses the GitHub Actions publishing source and `.github/workflows/pages.yml`. After an authorized deployment, wait for the workflow to succeed and verify the live page. Preserve the project subpath and hash-based case links.

## The case page

The page shows what the data holds and never rewrites a quotation. Each behaviour below is driven by a backend export field, so change the data, not the template, to change what a case shows.

- **Passage** (`quote`, `tr`): the English translation comes first and the original follows under its own label, in the quotation marks of its language (`QUOTES`). An English original stands alone. A first line of up to six words without final punctuation becomes the label's heading; line breaks become paragraphs and "•" items become a list. The original always starts hidden behind "Show", marks included; once a reader opens one, later originals stay open for the rest of the session. An English original has no translation to lead with, so it is always shown.
- **Layout mode**: a case whose default text (the translation, or an English original) has more than 60 words (`LONG_WORDS`) gets a wider source column and a pinned law column; shorter ones keep two equal columns. The mode is fixed per case so switching versions does not move the columns. Below 640px the panels stack with the law text first.
- **Versions** (`versions`): one chip per language above the passage, merged when a version repeats the same page and wording, plus a "Page" selector when a language has several pages. Switching must not move the control or drop focus. `cut` on a version shows a fixed note that the publisher's own text ends mid-sentence.
- **Context quotes** (`ctx`): retained in the dataset but not displayed. The owner removed the "Also on the source site" section for the MVP to keep case pages simple. Keep the main passage and the separate scope disclosure intact.
- **Related cases**: case pages in the A1–A3 layouts end after the scope disclosure. The owner removed the bottom "N cases in [issue]" list for the MVP; the breadcrumb still links to the issue's cases.
- **Marked wording** (`marks`, `lawMarks`): the passage highlights every occurrence of each mark in the matching language, the law text highlights `lawMarks`, and a one-line key explains both. A case with no marks shows no highlights and no key. As of 18 October 2026 the 229 cases published then had source and law marks drafted and cross-reviewed by separate agents, and published on the live site; the cases added afterwards (399 in all) also carry marks. These are presentation reviews against retained research, not fresh legal or live-source checks. Correct source versions stay unmarked: this applies to the Thai Airways French passage and its English translation. See the backend's data format for how researchers add marks.

Display rules agreed with the project owner:

- Titles use the publisher in bold followed by the claim, set with plain `text-wrap: wrap`, not `balance` or `pretty`: balance splits a two-line title evenly, and Safari's `pretty` does much the same, so both break far short of the available width. A title or intro keeps its last two words together (`widow()`) so it never ends on one word. The same holds for the front-page and area-page intro lines and the country breakdown, which have no width cap. Keep `balance` only for headings in narrow columns, such as the issue headings on area pages, where the heading wraps anyway. A claim that already starts with the publisher's name ("Rail Europe says …", "Trainline’s …") is not preceded by it twice. A case with more than four publishers shows their number ("80 German embassies") instead of their names.
- Digit ranges such as 7–14 and citation groups such as 5(1)(c) never break across lines. This uses non-breaking spans, so copy and search still work.
- Every area on the front page shows its applicable law (`lawShort`, for example "German law", "EU law" or "EU and German law"), government areas included, so rows look alike. The law comes first. Company areas add where the cases come from: "EU law · 4 countries, 19 institutions" on the front page, or "German law · 6 institutions" when the cases come from one country. The area page spells it out ("Cases from 14 countries and 32 institutions"). Institutions are the distinct publishers of the area's cases. Government areas count institutions the same way ("German law · 54 institutions"). The one exception is visas and passports: its publisher names are written inconsistently (one case can name a dozen embassies), so it counts countries ("EU and German law · 61 countries"), which there only mark where an embassy sits.
- The front page lists each area's first four issues and "and N more issues"; the area page lists them all.
- The header shows the logo (white not-equal sign on the dark header tone) beside the title; both words use the ink colour, with no red or green because those colours mean claim and law elsewhere.

## Institution pages

A second way in beside the issue pages: the **Issue sweeps / Institution sweeps** switch on the front page, a **group page** for each cohort ("Jobcenters") and an **institution page** for each member. All of it is driven by `DATA.groups` (exported from the backend's `subjects/institutions/`); with no groups the page, its routes and its markup are exactly as before, so a build without group data changes nothing visible.

- **Routes** (layout A1 only): `#A1.inst`, `#A1.group.<groupId>`, `#A1.entity.<groupId>~<entityId>`. Unknown ids fall back to the front page.
- **Front page, Institution sweeps:** built like Issue sweeps so switching only re-slices it. The two sections carry the same headings as Issue sweeps (`SECTOR_SCOPE`), the stats line has the same form ("669 institutions · 3,245 checks · 173 checks found a misrepresentation" beside "12 areas · 104 issues · 416 cases"), each with a one-line note defining its unit (a check is one institution on one question and several can rest on the same published case; a case is one published finding that can cover several pages or institutions), and the switch has no counts. A check and a case are different units: the 173 checks rest on 141 cases. A row reads title and "N checked", then "law · N institutions" (embassies add "in N countries"), then the bar, then "41 of 300 had a misrepresentation" (the group page says the same). A second line says how many of the institutions with no misrepresentation found lacked guidance on at least one question ("226 of the 247 with none found lacked guidance on at least one question", "All 27 …" when every one did; left out when none did), so the grey is not read as cleared. The group page carries the same line under its figure. The bar's colours are explained once by a legend beside the switch; it drops under the switch on phones. A section heading's count stays on one line; below 400px the count wraps under the heading.
- **Group page:** lede, summary bar with legend, then one block per question, built like an issue on the area page (the same `.issue` grid): the question title, its sentence, a "Law" line, "N of M had a misrepresentation" with its bar and one action on the left ("What the law says" opens the statute text and provision link in place; it is left out for a question with no issue page). The panel shows the question's own text (`lawText`, `prov`, `lawUrl`) when the group file has it; otherwise the linked issue's explanation, which carries the note "This explains the whole issue and has not yet been checked against this question" unless the question is marked `basis: "issue"` (a reviewer confirmed the issue's text answers it). Showing the issue's text under that note is a choice; hiding it until reviewed is a one-line change in `questionBlocks`. A link from a question to its issue page was removed on 21 October 2026: its count was of cases, the group lists institutions, and for several questions it added nothing the block did not already link to. The issue page still links back to the group; on the right the group's institutions with a misrepresentation as area-style rows ("Jobcenter Rastatt says …" with an arrow to the case). The first three show (two on phones) and "Show all N" opens the rest in place, moving focus to the first new row; a block with four or fewer shows them all. A question with none shows "No misrepresentation found on this question." Rows are built from the group's own results so each list adds up to its count (the issue page may list other cases). A claim is written to follow its publisher: lower-case and capitalised verbs follow the name directly (a case shared by several publishers is worded in the plural, so a single institution's row and card turn its first verb singular: "say" becomes "says"); a claim that opens with a noun ("Its conditions …") follows an en dash. Then a directory: search, a state select (only when there are at most 40 values; a group can name its own region word, such as "country" for embassies, which are searched by country) and "Show more". The questions are listed once, one per line and numbered, beside a key to the squares, and the table lists every institution in the group, worst results first: name (with its state or operator under it), one square per question (numbered like the key, with an outline for not addressed or not found) and "N of M" in red when it has misrepresentations. Rows are whole-row links to the institution page. The earlier "With a misrepresentation / All" filter was removed because the question blocks above already list every institution with a misrepresentation. Controls update in place so a clicked control never moves or loses focus. A search with no match says so.
- **Issue page (A1 only):** the topic route `#A1.topic.<area~topic>` is a page of its own, not the area page scrolled to the issue: crumbs, the issue's title as h1, Law and Sources keys, law text with provision, every source row, and "All N issues in <area> →" at the end. Other layouts keep the scrolled area page. A line "Also checked institution by institution: <group>, N of M had a misrepresentation →" appears on every issue that a group question points to, whichever way the reader arrived.
- **Origin in the URL:** the institution branch hands its origin to the pages it shares with the issue branch as a fourth hash part, `from-<groupId>` or `from-<groupId>~<entityId>` (`href(L, kind, id, from)`; `state().from`, A1 only, ignored when it names no group or institution). Group question rows and the institution cards' "Read the case →" open the case with it, so its crumb reads "All institutions / <group> / <institution>" and a line "Issue: … →" links to the issue (carrying the group); "Read the issue" opens the issue page with it, so its crumb starts "← <group>". Without it, both pages show the issue-branch crumbs as before.
- **Institution page:** one card per question with a result footer (label, one sentence for misrepresentation, unclear and not-found results, "Page checked" link; a "Run by" line names the company where the data has one, as for mobile brands). From 801px each card is one row, question left and result right, so no card stretches into an empty band; below that they stack. A clean result carries its label only, because the note at the bottom explains the method. When every question was read on the same page, that page is named once in the header and not on each card; page links show the host and the last path segment ("bahn.de/…/rechtliche-regelungen"), never cut mid-word. The line above the name appears only when it adds the state ("Jobcenter · Berlin"); the back link already names the group. "Misrepresentation" always links to a published case. Findings that lack a published case show as "Not yet published" and are never counted as misrepresentations.
- **Labels:** Misrepresentation, Unclear, Not addressed or not found, No misrepresentation found, Not yet published (in the legend only for groups that have such rows). The page says "No misrepresentation found", not "correct": many negative results were not independently reviewed.
- **Display rules agreed with the project owner:** no "not a ranking" note (the group lede states how many were checked on how many questions); question text uses the full card width; questions and results sit in concise cards, one per row from 801px; red stays "what the source says"; the result squares carry text and an `aria-label` as well as colour. The bar on a group page and front-page line counts institutions, each coloured by its worst result (misrepresentation, else not yet published, else unclear, else no misrepresentation found), so its red part matches the "N of M had a misrepresentation" figure; the question blocks count institutions per question; check totals are written in words and never drawn on the same bar.
- **Data:** see the backend's data format ("Institution groups"). Question sentences and law lines are editorial text in the group file, not derived from the sweep.
- **Checking a change:** `node tests/check_routes.cjs dist/index.html dist/data.json` renders every group and institution route (and checks that, without groups, no institution switch appears); then follow the checks above in the browser at 320, 390, 768 and 1280, light and dark.

## Systemic sweeps pages

A third way in beside Issue and Institution sweeps: the **Systemic sweeps** pill, an overview of German cities and a page for each city. All of it is driven by `DATA.systemic`, made by the backend from `subjects/systemic/germany.json` (see the backend's data format, "Systemic site file"). With no systemic data the pill, the routes and the data are exactly as before; the build output without it is unchanged. Layout A1 only.

- **Routes:** `#A1.sys` (overview) and `#A1.city.<AGS>`. An unknown city or a build without systemic data falls back to the front page.
- **Switch (30 October 2026 design review, N4 with H4):** the sweep switch is part of the header bar, right-aligned beside the theme button, as a flat segmented control (a grey strip, the current tab a white chip). With systemic data the tabs read "Issue sweeps", "Institution sweeps" and "Systemic sweeps". `lensRow()` builds it and hands it to `siteBar()` through `lensNav`/`takeLens()`; it appears on the three front pages only, as before. Below 760px the header takes a second row for it, and at 380px and below the word "sweeps" is hidden (`span.x`). On Institution sweeps the bar legend sits under the statistics (`.lens-row`). The title has 24px of space under the bar. The tabs are 28px tall on desktop (44px on phones); an underlined-tab style (H1) was the alternative.
- **Overview:** one mark per city (a dot when districts are shown, a square otherwise), packed in state blocks by number of cities, largest city first; Berlin, Hamburg and Bremen (with Bremerhaven) form one "City-states" block of named links. A state block's header is the state name alone, followed by two groups, districts first (as the level above the cities): "N districts" above the district squares and "N cities" above the city dots, the groups (`.sy-grp`) separated only by space, because each state is a white card with a 1px border and a 10px radius laid out in a grid of columns at least 300px wide that reads left to right in order of city count (V5; the earlier CSS columns read down each column instead) (V2 of the 30 October 2026 proposals; the 2px left rule of P3 was tried first and dropped once the cards existed; the firm-rule and one-row-per-state styles were the alternatives), in the same small grey style (the "190 of 243" figure was removed on 30 October 2026 because it counted cities only and confused readers beside the districts); the statistics under the intro are the only counts of misrepresentations. The result classes are Misrepresentation (at least one confirmed finding), Unclear (no confirmed finding, at least one unclear), No misrepresentation found (substantive screening recorded, nothing confirmed) and Not yet inspected (an empty outlined square: listed, or only discovery or access-limited records). The chips beside the search filter by class and show their counts. Hovering names a city; on a touch device the first tap selects a square and names the city, and tapping it again opens its page. The search lists matches as links so a keyboard reader needs no square; squares are not tab stops. No rate or ranking is shown, and the note says why. The statistics under the intro say only "inspected", never "listed": one line per kind with its square or circle ("938 cities inspected · 758 (81%) with a misrepresentation", "43 districts inspected · 38 (88%) with a misrepresentation") and a small note, "Misrepresentations in all: 1,594 on city websites, 103 on district websites." The percentage is the share of the places inspected so far (`sysSumLine`); the owner asked for it on 30 October 2026, replacing the earlier "no share" rule. "How to read this" says it is not a rate for German cities or districts, because places were not inspected to the same depth and the districts were chosen by hand, and that places should not be ranked by it. The definition of a misrepresentation sits in "How to read this", unlike the other two tabs, which keep their one-line note under the figures.
- **City page (layout M1 of the 29 October 2026 proposals, with the S1 and S3 changes of the 29 October design review):** crumb, state and population, name, then a count of what was found (a square, a figure and a word each: "7 misrepresentations", "2 unclear", "6 pages with nothing found"; a zero is left out) and one line, "15 service pages read on 28 Oct 2026. Results describe only those pages." A page with no finding and no page read keeps one sentence instead. Then one row per finding, and the row is the disclosure: its summary holds the result and the service beside it in the same size and weight ("Misrepresentation Unterhaltsvorschuss": the service is the page title the research recorded, cut at a dash or colon and at 64 characters, with no dot on phones where a long one wraps below) and the claim, with a chevron at the right. A closed row shows at most four lines of the claim and opening it shows the rest. Opening a row shows the "Page checked" link with its date, then the passage and the law side by side. No row is open when the page loads; only one is open at a time, so opening one closes the others, and the row does not move when it opens. A passage the research has not translated is shown in German with a note. A claim written in German carries a "Claim in German" tag. "Pages read" lists every page with its result and is open when there is no finding. A city nobody has read says so and is never shown as cleared. The "What this shows" note limiting the result to the pages read sits under the count header as a disclosure (a page with no count header keeps it at the end). From 960px the crumb and header form a sticky left column of 300px and the findings a column up to 720px beside it, so the chevron stays near its claim; below 960px it is one column.
- **Districts (Landkreise):** `DATA.systemic[0].districts`, from the backend's `subjects/systemic/germany-districts.json`, is optional like the rest; without it nothing below shows. Each state block with districts lists them first: "N districts" and a row of squares, then "N cities" and a row of dots, both coloured by the same four results (the shapes swap only when district data is present; without it cities stay squares, `.sy-bands.mixed`); the district line of the statistics is never added to the city figures, the chips and state counts stay city counts, and the caption says so. Search and the hover or tap line cover both. The intro reads "Websites of the 1,000 largest German cities and all German districts, checked against federal and EU law." (30 October 2026; without district data it names the cities only), so the district scope is the whole roster, not the districts inspected so far. Every district on the roster is drawn, in code order within its state: a district nobody has read is an empty circle ("Not yet inspected", its page says nobody has read it), the same style as an uninspected city. The districts that have been inspected were hand-picked, not a sample: no rank or population, and the "How to read this" note and each district page say so (the percentage beside the district count is a share of those inspected, not of all districts). `#A1.district.<code>` is the same page as a city's (eyebrow "State · District", the authority beside the website link, no population line); a district code is never a city route and the other way round. The service beside each result drops the authority from the title ("Landratsamt München: Wohngeld" shows "Wohngeld"; "— Kreis X" and "| Kreis X" are cut) and shows nothing for a bare record id such as "wartburg-basic".
- **Data notes:** passages are shown as the research records them. Since 30 October 2026 the headline, law text, citation and unclear reason of 2,097 findings (of 2,283) are plain-English rewrites from the backend's overlay (`research/systemic-sweeps/germany/plain/`). All current findings have completed the rewrite process; the remaining 186 site entries need additional research and retain their original wording. Their research gaps are recorded in the overlay. The site data must be built with the backend's `plain/build-site.sh`: a plain `python3 run.py build` reverts the rewrites. Findings carry no service-field tag, so the pages have no field view.
- **Checking a change:** `node tests/check_routes.cjs dist/index.html dist/data.json` renders the overview and every city page, checks that each city shows one row per finding and that an unknown city or missing data falls back to the front page; then check the pages at 320, 375, 390, 768 and 1280, light and dark.

## Checking a change

- After a rebuild run the route test, check the inline JavaScript syntax, and open the affected pages at 320, 390, 768 and 1280px. When a change should leave other pages untouched, render every case and area page with the previous and the new build and compare the markup; do this for any change to passage rendering.
- Playwright is not installed and must not be installed without the owner's approval. Measure in the built-in browser. Headless Chrome cannot render below about 500px, so take narrow screenshots inside an exact-width frame (an iframe of the target width). Its dark mode setting did not apply; check dark mode in the browser pane.
- Previews of proposed changes are made by injecting temporary CSS and JavaScript into a copy of the built page. Never edit `src/` or `dist/` to preview an idea the owner has not approved.

## Open design proposals

A review of 18 October 2026 produced ten proposals. Built and published: the version switcher, wider titles, kept-together ranges and citations, and shorter front-page issue lists. Not built, so do not treat them as decided; ask the owner first:

- Stack the compare panels up to 900px instead of 640px (at 768px the law column is only about 300px wide).
- Treat only a first line of three words or fewer as a heading, so a six-word table header stays in the passage.
- Give every disclosure row a 44px tap area on phones.
- Optional: put the hypothetical example after the passage on stacked layouts; add an issue jump list to area pages with five or more issues.

Other treatments for marked wording (spotlighting whole sentences, numbered markers with a "what differs" line, folding the unmarked text) were previewed and not chosen. Folding text is only safe if researchers mark which text may be hidden, because the unmarked text often holds the qualification that makes a finding fair.

Known data issues the page works around or shows as they are:

- Three cases list an identical version twice (`airlines-thai-airways-timing`, `roaming-vodafone-pt-net-label`, `roaming-lebara-current-examples`); the page merges them.
- Five rail claims start with the publisher's name, so titles would repeat it (`rail-sncf-connect-ouigo-voucher-only`, `rail-sncf-connect-ouigo-refund-fallback`, `rail-omio-through-ticket-force-majeure`, `rail-raileurope-retailer-prior-notice`, `rail-trainline-trenitalia-sixty-minute-band`); the page drops the repeat.
- Some passages run a source list together as plain text (for example `rail-raileurope-retailer-prior-notice`); the page can only build a list from line breaks and "•".
